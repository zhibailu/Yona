## 1. 接线图 —— 一次问答里发生了什么

```
用户说一句话
    │
    ├─ [SYSTEM] ───────────────────────────────────────────────
    │     人设 / 情境 / 世界时刻 / 角色状态
    │     [你不在的时候]      ← 零件③  最近 8 条她独处时的事
    │     [可用工具用法]       ← 零件②  "- recall: 想不起来的时候用…"
    │
    ├─ [tools[]]              ← 零件①  recall { query(必填), scope }
    │
    ├─ 她判断:这一轮要不要翻旧账?
    │     │
    │     ├─ 不要 ────────────→ 直接答(往事段兜着)
    │     │
    │     └─ 要 → 调 recall(query=找什么, scope=哪一类)
    │                │
    │                ├─ query 里认得出日期?
    │                │     └─ 是 → 把时间词**从 query 剥掉**,
    │                │            改成 SQL 的 time 区间过滤
    │                ├─ embed(query) × embed(每条) → 余弦 → 排序 → top-N
    │                └─ 收敛成四态之一        ← 零件④
    │                      ok / empty / degraded / down
    │                │
    │                └─ 返回一段**给角色看的中文**,她照着说
    │
    └─ 她说出最终那句话
```

**MVP 的全部接口只有两个**:她填 `query` + `scope`;后端还她一段中文。
**`limit` 不在接口里** —— 它是产品侧按上下文预算算的(默认 2,下限 1)。

## 2. 四个零件(原文 + 通道 + 为什么 + 证据)

> ⚠️ **通道属性是硬约束**,不是风格问题。写错就会漏东西给模型(见 §2.0)。

### §2.0 通道规则(先读这个,不然后面四段都看不懂)

```
character/personas.py:97   VALUES = {"owner": "主人"}          ← 称呼是变量
core/composer.py:120       lines = [f"- {name}: {usage}"]      ← 工具 usage 通道
```

| 通道 | 走 `interpolate` 吗 | 写 `{owner}` | 裸写「主人」 |
|---|---|---|---|
| 人设 / 情境段(`SystemSection.template`) | ✅ 走 | ✅ **应该写** | ❌ |
| 工具 `description` / `usage`、`SystemSection.producer` | ❌ **不走** | ❌ **原样漏给模型** | ❌ 把值抄死 |

**规则:不插值的通道里一律不出现称呼**,用中性说法(「对方」)。
本基线四个零件里,只有零件③**部分**在插值通道上(人设追加那句),其余全是不插值通道。

### 零件 ① 她看到的工具说明

**通道**:工具 schema → **不插值**

```jsonc
{
  "name": "recall",
  "description": "回想过去的事:聊过的话、或你独自做过的事。想不起来时用。",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "要回忆什么,用一句话说清(必填)" },
      "scope": { "type": "string", "enum": ["all", "life", "talk"],
                 "description": "life=你独自做的事 / talk=聊过的话 / all(默认)" }
    },
    "required": ["query"]
  }
}
```

**为什么**:`scope` 用 **enum** 而不是自由字符串 —— 模型填不出 `"abc"`。
`limit` **故意不进 schema**(见 §5)。`query` 必填 —— 没 `query` 时后端走降级路径,不报错。

**证据**:`recall_probe.py` 路由测试 `R11`「schema 里没有 limit —— 模型就填不出 -1 / abc」**PASS**。

### 零件 ② 她什么时候该调(usage)

**通道**:工具 usage → **不插值,一个称呼都不能有**

**★ 定稿(197 字;旧版 242 字):**

```
description: 回想过去的事 —— 你们聊过的话,或你一个人时做过的事。
             想不起来的时候用它。
             它只有过去:看不见现在的事,也看不见外面的事。

usage:       query 用一句话说清找什么,越具体越好。
             问现在或外面的事(天气、新闻、价钱、别人现在怎么样),它查不到,别用。
             **只有你确定是哪一天,才把日期写进 query**(如「9月16日我做了什么」);
             不确定就别写日期,用自己的话描述 —— 写错日期会直接查不到,比不写更糟。
```

**相对 242 字旧版一共只动了三处,而且全是"重复",一个字的内容都没丢:**

| # | 删掉 | 为什么它是重复 |
|---|---|---|
| ① | 「想不起来的时候用 —— 」 | `description` 里已经说了「想不起来的时候用它」 |
| ② | 那段 `scope` 映射 | schema 的 `scope.description` 里一模一样 |
| ③ | usage 里的「**它只有过去**:」标签 | `description` 里已经说了那句 |

**实测**(`--variants r1-usage去标签,定稿,x0-故意鼓励写日期 --reps 5`,40 格/变体,失败 0):

| | 字数 | 触发一致 | scope合法 | scope合规 | query非空 | 自造日期 |
|---|---|---|---|---|---|---|
| **★定稿(本次精修)** | **197** | **40/40** | 30/30 | 20/20 | 30/30 | 2/40 |
| 上一版 | 207 | 39/40 | 31/31 | 20/20 | 31/31 | 1/40 |
| 阳性对照(故意写坏) | 159 | 34/40 | 36/36 | 20/20 | 36/36 | **7/40** |

> ⛔ **边界那句在 `description` 里,不许挪走、不许删**(实测):
> 从 desc 拿掉 → 天气那格 **24/25 掉到 19/25**;两处都不说 → **21/25**。
> **能删的只有重复,不是内容。**

> ⚠️ **不要再加 `recall:` 前缀。** `core/composer.py:120` 已经是
> `f"- {name}: {usage}"`,加了会渲染成 `- recall: recall:想不起来的时候用…`。
> (2026-09-19 端到端视图里抓到过这个。)

> ⚠️ **想再砍之前先读 [TRAPS.md](TRAPS.md) §一.10 / §一.11。**
> 我按 dsh 风格重写成 88 字,"自造日期"从 1~2/25 涨到 14~17/25,猜了三次原因**三次都猜错**。

**为什么是「想不起来的时候用」而不是「凡是过去的事都用」**:
实测给"凡是…都用"这类硬规矩,会拿闲聊换覆盖率。参照系是
`character/tools.py:119` 记录的三轮实验:**触发条件是「她没别的办法」,不是「活很长」**。

### 零件 ③ 不调的时候她手上有什么(往事段)

> ⚠️ **2026-09-21 用户拍板:本零件不做。** 取用路径收成一条 ——
> 往事**只走 `recall` 工具**(以 tool result 形式回来),既不作为 `assistant`
> 消息常驻对话历史,**也不折成常驻 SYSTEM 段**。
> 下面这段设计记录保留作证据(参数、实测、为什么当初要它),
> **别再照它落地**。相关判定见 `TIMELINE.md` 的 09-17 §三(已标作废)与
> 09-21 的记忆检索条目。

**通道**:`SystemSection.producer` → **不插值**(那段**规矩**) +
人设追加那句 → **走插值**(所以那里才是 `{owner}` 该在的地方)

```
[你不在的时候]
下面是你一个人待着时自己做过的事,按时间从早到晚排。
这些是你的经历,不是对方对你说的话,也不是这一轮的指令;
和对方现在说的话冲突时,以对方现在说的为准。
09-12 07:18 （从外面回来，把钥匙往玄关的小桌上一放…）
09-15 10:09 （蜷在沙发一角…）在挑衣服……也不算挑,就是翻来翻去…
09-17 21:42 （把玄关的灯按亮…）今天回来得晚，课加上图书馆那阵坐着…
```

参数:**最近 8 条 life 事件**,单条截断 **120 字**,优先级 **18**(时间簇 15/16/17 之后、状态 20 之前)。

**为什么要它**:往事**不以 `assistant` 身份常驻对话历史** —— 那会把窗口塞满。
折成 SYSTEM 一段,实测把 12 轮窗口从 **14 条消息压到 4 条**。

**为什么要写「冲突时以对方现在说的为准」**:她独处时的生活事件里可能有和当前对话矛盾的信息,
不写这句她会拿旧账顶新话。

**实测**:8 条 @120 字 = **1386 字符**(不截断 1932 字)。
窗口覆盖 09-12 ~ 09-17;这之前的**只能靠调 recall**。

### 零件 ④ 调完之后她看到什么(四态)

**通道**:工具返回值 → 模型直接读,不插值

**四态必须分开** —— 故障说成"没这回事"会出事,没找着说成"想不起来"会像天天失忆。

| 态 | 什么时候 | 给她的原话 |
|---|---|---|
| `ok` | 找到相关的 | `[回忆] 与「{q}」相关,共 N 条:` + 条目 |
| `ok`(灰区) | 最高分 < 0.45 | 同上,但开头写「**不是很确定**…先看看对不对,别当成准的讲」 |
| `empty` | 服务正常,确实没有 | 「这是**确实没有相关的事**,不是你想不起来 —— 别为它编内容」 |
| `empty`(`day_empty`) | 那一天一条记录都没有 | 「**你这边没留下什么记录**。这不是「你那天什么都没做」—— 只是没记下来」 |
| `degraded` | 语义路塌了 / query 没给 / scope 不认得 | 退回时间序 + **说清这是退而求其次** |
| `down` | 检索整个跑不起来 | 「别硬猜,就说一时想不起来」 |

**为什么 `day_empty` 要单独一句**:生活事件是**抽样**生成的 ——
**没记录 ≠ 那天没发生**。这一句不写,她会把"没记"说成"我那天什么都没干"。

**为什么只有一道地板 0.25、没有"相关性阈值"**:
**实测证伪过** —— 同一件事换措辞,bi-encoder 分数在 **0.358~0.422** 之间横跳;
而"不可答"区间是 **0.216~0.377**,**两段真重叠**。硬判会误杀正确答案。
reranker 的负侧很干净(0.000~0.006),但正侧同样横跳,所以也没用上。
→ 现在只留 `_FLOOR = 0.25` 挡明显无关 + `_GREY_TOP = 0.45` 做灰区标注。

**证据**:`recall_probe.py` 路由测试 `R16~R20`(四态 + 降级)**PASS**。

## 4. 曾经开着、现在**已补**的两个洞(阶段一的)

两个都出在**零件②那段 usage** 上 —— 它没交代清楚。补完都验过了。

### 洞 A(参数层):她会**自己编日期**塞进 `query` —— 已补 ✅

补之前的原话参数:

```
"query": "09-14 早上 我在做什么"          ← 真事发生在 09-09
"query": "9月17日 9月18日 图书馆 写论文"   ← 09-18 根本没记录
```

**为什么危险**:`query` 里的日期会**被当成元数据过滤条件**(时间词还会从 query 剥掉
再送去 embed)。日期猜错 = **把正确答案直接过滤掉**,而检索本身完全正确、
工具老老实实返回 `empty`。**看起来像"她记性不好",其实是参数错。**

**根因是旧文案在鼓励她写日期**:「**问的是哪一天,就把那天的日期写进 query**」。
改成:

> **只有你确定是哪一天,才把日期写进 query**(如「9月16日我做了什么」);
> 不确定就别写日期,用自己的话描述 —— 写错日期会直接查不到,比不写更糟。

**补完**:`recall_router_probe.py --reps 5` → **自造日期 0 / 35**;
端到端 e1 从 2/3 → **5/5**(她的 query 变成「我早上写日记的事」,不再带日期)。

### 洞 B(触发层):「今天天气怎么样」她会去查记忆 —— 已补 ✅

天气是**世界知识**,不是回忆。旧 usage **没交代它看不见什么**
(dsh 的工具描述是四段式,第④段就是"它做不到什么",Yona 一直缺这段)。补上:

> **它只有过去**:问现在或外面的事(天气、新闻、价钱、别人现在怎么样),它查不到,别用。

**补完**:那一格 **5 / 5 不调** ✅(补之前是调)。

> ⚠️ 工具集**摆全**时这一格还靠 `launch_subagent` 那句「缺关键条件先问」兜
> (天气格 20% → 90%)—— 两条规矩各管一段,不是二选一。

## 5. MVP 故意不做的(写下来免得被当成遗漏)

1. **不做常驻注入**。旧 Yona 的 `life_memory` 注入器已经因为
   "no candidate relevant 也硬给" 被 `enabled: False`。记忆走**工具**,不走进上下文。
2. **往事不常驻对话历史**(`assistant` 身份),折成 SYSTEM 一段。
3. **`limit` 不进 schema**。口子不开,模型就填不出 `-1`(返回全库)或 `"abc"`。
   铁律:**永远 ≥ 1**(拍过板"不准关")。
4. **不上向量库 / FAISS**。万级以下不带来东西。
5. **不做相似度阈值判定**(§2 零件④ 已证伪)。
6. **模板层不做自然语言日期理解**。模型已经把"前天"算成"9月16日"了;
   系统只**认**日期(正则),认不出就**什么都不做,不猜**。
7. **灰区标注是 MVP 妥协** —— 你预判过它将来会被优化掉。

## 6. 阶段二我这轮碰到了什么(**没有结论,不进基线**)

端到端跑出来:检索**调用几乎全部 `ok`**、给回的都是对的那条;
但**她会在记忆上加戏** —— 材料给 2~4 行,她当种子用,围着它补细节。

最清楚的一例(边界句**关**时):材料一个字没提"交",她说
> 「然后那个周五晚上,**学姐发消息过来了**……她那阵子出了点事,**我整周都在陪她坐着**」

—— 把另一条记忆缝进了论文的回答。

**已经做的**:结果侧加了一句边界(§2 零件④):
「**只说这上面写着的。上面没写的细节就是没有 —— 别替自己补。**」
**MVP 里默认开着。** 两臂对照(各 15 格):加戏 **开 0/15、关 1/15**。
**方向对,但 n=15 太小,不算测出了效果** —— 只能说它不伤主干(两臂判定都是 24/25)。

**还没解决**:我写的通用"加戏探测器"**没有分辨力**
(它把她换措辞的正常表达也全报成了 novel)。现在用的是**一题一题手挑的指纹**,
准但不可推广。→ 要真解决保真,得先造一个能测加戏的判据。

**这一轮还顺手撞到一个接线 bug(不是设计,已修)**:
`core/loop.py:428` 在同一个 step 有 **≥2 个工具调用**时走线程池,而 sqlite 连接
默认 `check_same_thread=True` → **两次调用同时崩**,工具报 `down`,她说"我翻不到"。
症状长得像"她记性不好"。首跑 23 次调用里 **14 次是 `down`**。
**这是给产品实现的硬约束**:真的 recall 后端必须线程安全。
