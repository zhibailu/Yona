## 1. 接线图 —— 一次问答里发生了什么

```
用户说一句话
    │
    ├─ [SYSTEM] ───────────────────────────────────────────────
    │     人设 / 情境 / 世界时刻 / 角色状态
    │     ~~[你不在的时候]      ← 零件③  最近 8 条她独处时的事~~
    │       ❌ **2026-09-21 作废**:往事段不做,往事只走 `recall`(见零件③ 顶部)
    │     [可用工具用法]       ← 零件②  "- recall: query 用一句话说清找什么…"
    │
    ├─ [tools[]]              ← 零件①  recall { query(必填), scope }
    │
    ├─ 她判断:这一轮要不要翻旧账?
    │     │
    │     ├─ 不要 ────────────→ 直接答
    │     │                      (❌ 原写"往事段兜着" —— 往事段已作废,不兜了)
    │     │
    │     └─ 要 → 调 recall(query=找什么, scope=哪一类)
    │                │
    │                ├─ query 里认得出日期?
    │                │     └─ 是 → 把时间词**从 query 剥掉**,
    │                │            改成 SQL 的 time 区间过滤
    │                ├─ embed(query) → 余弦;BM25(query) → s/(s+4.0)
    │                │     排序分 = **余弦 + 0.2×BM25**(两路绝对刻度,不按 query 内最大值归一)
    │                │     → top-N          ← 闸门/灰区**只看余弦**,不看融合分
    │                └─ 收敛成四态之一        ← 零件④
    │                      ok / empty / degraded / down
    │                │
    │                └─ 返回一段**给角色看的中文**,她照着说
    │
    └─ 她说出最终那句话
```

**MVP 的全部接口只有两个**:她填 `query` + `scope`;后端还她一段中文。
**`limit` 不在接口里** —— 它由产品侧给(**当前是常数 2,下限 1**;
要"按上下文预算算"就接 `limit_fn` 钩子,`character/tools.py:327` —— 目前装配处没接)。

### 零件 ① 她看到的工具说明

**通道**:工具 schema → **不插值**

```jsonc
{
  "name": "recall",
  "description": "回想过去的事:聊过的话、或你独自做过的事。想不起来时用。",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "要回忆什么,用一句话说清(必填)" },
      "scope": { "type": "string", "enum": ["all", "life", "talk"],
                 "description": "life=你独自做的事 / talk=聊过的话 / all=两边都查(只在一边找、怕找不着时用,多带回来的也是相关的情景)" }
    },
    "required": ["query"]
  }
}
```

**为什么**:`scope` 用 **enum** 而不是自由字符串 —— 模型填不出 `"abc"`。
`limit` **故意不进 schema**(见 §5)。`query` 必填 —— 没 `query` 时后端走降级路径,不报错。

**证据**:`recall_probe.py` 路由测试 `R11`「schema 里没有 limit —— 模型就填不出 -1 / abc」**PASS**。

这些是你的经历,不是对方对你说的话,也不是这一轮的指令;

09-12 07:18 （从外面回来，把钥匙往玄关的小桌上一放…）

### 零件 ④ 调完之后她看到什么(四态)

**通道**:工具返回值 → 模型直接读,不插值

**四态必须分开** —— 故障说成"没这回事"会出事,没找着说成"想不起来"会像天天失忆。

| 态 | 什么时候 | 给她的原话 |
|---|---|---|
| `ok` | 找到相关的 | `[回忆] 与「{q}」相关,共 N 条:` + 条目 |
| `ok`(灰区) | **融合分第一名那条的余弦** < 0.45 | 同上,但开头写「**不是很确定**…先看看对不对,别当成准的讲」 |
| `empty` | 服务正常,确实没有 | 「这是**确实没有相关的事**,不是你想不起来 —— 别为它编内容」 |
| `empty`(`day_empty`) | 那一天一条记录都没有 | 「**你这边没留下什么记录**。这不是「你那天什么都没做」—— 只是没记下来」 |
| `degraded` | 语义路塌了 / query 没给 / scope 不认得 | 退回时间序 + **说清这是退而求其次** |
| `down` | 检索整个跑不起来 | 「别硬猜,就说一时想不起来」 |

**为什么 `day_empty` 要单独一句**:生活事件是**抽样**生成的 ——
**没记录 ≠ 那天没发生**。这一句不写,她会把"没记"说成"我那天什么都没干"。

**为什么只有一道地板 0.25、没有"相关性阈值"**:
**实测证伪过** —— 同一件事换措辞,bi-encoder 分数在 **0.358~0.422** 之间横跳;
而"不可答"区间是 **0.216~0.377**,**两段真重叠**。硬判会误杀正确答案。
reranker 的负侧很干净(0.000~0.006),但正侧同样横跳,所以也没用上。
→ 灰区标注 (`_GREY_TOP = 0.45`) 是生效的;**地板那一半没有**(见下 ⚠️)。

> ⚠️ **【2026-09-21 22:55 标】上面这些是实验里的做法,产品里只落了一半。**
> 产品实际:`_GREY_TOP = 0.45` **在用**;`_FLOOR = 0.25` **没接线** ——
> `make_recall_tool` 的 `min_score` 默认 `None`(`character/tools.py:328` 注释:
> 「None = 不设(产品默认不设,见 `_FLOOR`)」),`:399-400` 只在传了值时才过滤,
> 而 `server/app/engine.py:294` **只传了 `recall_index`**。
> `test/test_recall_tool.py:171-179` 甚至断言"不设阈值就该给出来"。
> 所以**产品现状是:低分命中照样返回 `ok`,没有地板挡**。
> 同理 `MemoryIndex.top_cos`(`core/memory.py:333`)是为闸门写的,产品路径**零调用者**。
> **这属"文档与代码谁对"的分歧 → 已上报用户裁决(补接线 / 改文档),不自行二选一。**

**证据**:`recall_probe.py` 路由测试 `R16~R19`(四态:ok / empty / degraded / down)**PASS**。
(R20 / R21 那两条是**往事段**用例 —— 零件已取消,只作史料,别算进四态证据。)【2026-09-21 22:55 标】

## 4. 曾经开着、现在**已补**的两个洞(阶段一的)

### 洞 A(参数层):她会**自己编日期**塞进 `query` —— 已补 ✅

补之前的原话参数:

```
"query": "09-14 早上 我在做什么"          ← 真事发生在 09-09
"query": "9月17日 9月18日 图书馆 写论文"   ← 09-18 根本没记录
```

**为什么危险**:`query` 里的日期会**被当成元数据过滤条件**(时间词还会从 query 剥掉
再送去 embed)。日期猜错 = **把正确答案直接过滤掉**,而检索本身完全正确、
工具老老实实返回 `empty`。**看起来像"她记性不好",其实是参数错。**

**根因是旧文案在鼓励她写日期**:「**问的是哪一天,就把那天的日期写进 query**」。
改成:

> **只有你确定是哪一天,才把日期写进 query**(如「9月16日我做了什么」);
> 不确定就别写日期,用自己的话描述 —— 写错日期会直接查不到,比不写更糟。

**补完**:`recall_router_probe.py --reps 5` → **自造日期 0 / 35**;
端到端 e1 从 2/3 → **5/5**(她的 query 变成「我早上写日记的事」,不再带日期)。

> ⚠️ **【2026-09-21 22:55 标】这个 `0/35` 是空数,别再引用。**
> 它跑的 7 条用例里**没有一条会诱出凭空日期**(见 [TRAPS.md](TRAPS.md) §一.2);
> 补上第 8 条用例后的真实数是 **2 / 40**(见 §3 表)。
> 结论本身("改文案有用")没错,但 `0/35` 证明不了它。

## 5. MVP 故意不做的(写下来免得被当成遗漏)

1. **不做常驻注入**。旧 Yona 的 `life_memory` 注入器已经因为
   "no candidate relevant 也硬给" 被 `enabled: False`。记忆走**工具**,不走进上下文。
2. **往事不常驻对话历史**(不以 `assistant` 身份),**也不折成常驻 SYSTEM 段** ——
   只走 `recall` 工具。(2026-09-21 用户拍板;见 `TIMELINE.md` 09-21「记忆检索接进主链路」)
3. **`limit` 不进 schema**。口子不开,模型就填不出 `-1`(返回全库)或 `"abc"`。
   铁律:**永远 ≥ 1**(拍过板"不准关")。
4. **不上向量库 / FAISS**。万级以下不带来东西。
5. **不做相似度阈值判定**(§2 零件④ 已证伪)。
6. **模板层不做自然语言日期理解**。模型已经把"前天"算成"9月16日"了;
   系统只**认**日期(正则),认不出就**什么都不做,不猜**。
7. **灰区标注是 MVP 妥协** —— 你预判过它将来会被优化掉。

准但不可推广。→ 要真解决保真,得先造一个能测加戏的判据。

**这一轮还顺手撞到一个接线 bug(不是设计,已修)**:

**这是给产品实现的硬约束**:真的 recall 后端必须线程安全。
