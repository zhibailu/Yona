# docs/pitfalls —— 踩坑与教训

> 放"哪次错了、错在哪、怎么避免"。两类:
>
> 1. **工程坑**(代码/文档自己写错):如人设身份句多处复制互相矛盾、文档与代码
>    语义不同步、STRUCTURE 陈旧矛盾(git init/_life/行数)。
> 2. **AI 与用户意志冲突 / AI 自己的错**:完整登记在根目录 `AI-GUARDRAILS.md §二`
>    (含守则),这里放由此沉淀的工程化教训与"怎么从流程上防"。
>
> 规则:
> - 每坑一行族:id · 症状 · 根因 · 修复/规避。
> - 发现旧文档与用户意志矛盾 → 建/并入本目录,报用户,**不默默二选一**。
